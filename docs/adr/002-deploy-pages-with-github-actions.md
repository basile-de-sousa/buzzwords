# ADR-002: Deploy GitHub Pages from a GitHub Actions workflow
Status: proposed - Date: 2026-09-26

## Context

SPEC-001 AC5 requires the site to be built and deployed to GitHub Pages on every push to `main`. The site is generated by a Node build (ADR-001), so the generated `_site/` must not be committed by hand, and a broken fiche must stop the deploy.

## Decision

Use the "GitHub Actions" Pages source: `.github/workflows/pages.yml` runs on push to `main` (and manually via `workflow_dispatch`), executes `npm ci`, `npm test`, `npm run build`, uploads `_site/` with `actions/upload-pages-artifact` and deploys with `actions/deploy-pages` (permissions `pages: write`, `id-token: write`; one `pages` concurrency group, deployments not cancelled). A separate `ci.yml` runs the same checks on every pull request. The repository's Pages source must be set to "GitHub Actions" once, in Settings → Pages.

## Alternatives rejected (and why)

- "Deploy from a branch" with a committed `gh-pages` branch: generated files in git history, an extra push token/action, and no clean link between a failing build and a skipped deploy.
- Serving `main` directly with GitHub's built-in Jekyll: cannot run the Node build or its validation.
- Another host (Netlify, Cloudflare Pages): an extra account and service for no benefit on a public, static, zero-cost site.

## Consequences

- Every push to `main` (including fiches committed straight by `/buzzword`) redeploys the site in about a minute; an invalid fiche fails the workflow and leaves the previous site online.
- One manual setting is required before the first deploy (Pages source = GitHub Actions).
- Deploys consume GitHub Actions minutes (free for public repositories).
